# Issue #195: bounded monitor implementation acceptance

The user approved the research gate on 2026-09-05. The implementation follows
the conditional proxy-first decision in [the research report](../../MULTICAM_MONITOR_RESEARCH.md).
This record qualifies the opt-in monitor on the tested Chromium host. It does
not establish unrestricted eight-camera playback or a total-process memory cap.

## Product behavior and ownership

Select a multicam item and enable **Live angle previews** in the Inspector,
then play. The active angle stays in Program Monitor. Inactive angles target
320×180 at 10 fps, with a single 160×90 / 5 fps fallback for tile-only pressure.
Program or audio budget failures retire the wall and explain how to retry.
Every angle button remains keyboard operable; existing cut commands and Alt+1
through Alt+8 use the integer playhead and existing fixed/follow-video audio
policy. Monitoring never changes authored data or supplies export frames.

| Total angles / source | Product admission |
|---|---|
| 2–4, 8-bit AVC originals up to 1080p | Conditional on source metadata, bounded GOP/read work, shared resources and a healthy Program baseline |
| 2–8, fresh production AVC proxies up to 720p | Preferred; still conditional on resource and runtime health checks |
| 5–8 with any inactive original, oversized original, unsupported codec/profile, stale or missing source | Paused/on-demand previews with a reason; manual editing stays available |
| Source Monitor, proxy/media analysis or export active | Those operations preempt the optional wall |

One shared app admission ledger reserves resources before essential owners
allocate. Program retains conservative high-water allowances until its bridge
is disposed. Audio reserves its entire clip plan; complex follow-video edits,
layered audio and layered Program compositions can therefore deny the wall even
if a particular instant appears cheap. This deliberately preserves playback
priority without relying on native decoder introspection.

The wall owns one worker, at most seven finite native decoders, one pending
request per angle and one scratch canvas. The 64 MiB wall and 256 MiB aggregate
limits count known RGBA-equivalent references/surfaces. Encoded data, source
Blobs, demux caches and opaque browser/native/GPU storage are additional. Packet
metadata is inspected before materializing payload: at most 60 packets, 2 MiB
per packet and 8 MiB submitted payload per request; reads and demux cache also
have independent bounds. Exact presentation timestamps, origins, coverage and
coded dimensions must match the source reservation. Unsupported media fails
closed to on-demand previews.

Normal off retains admission through an observed zero acknowledgement or a
100 ms close deadline. Urgent preemption terminates synchronously before the
lease is released. The recorded cleanup distinguishes termination from an
observed native-zero ledger, and closes transferred bitmaps even after a late
delivery. Hidden-page admission is refused. Source/proxy/project identity and
visibility are checked again after preparation and worker startup.

## Verification scope

The source-bound compact artifact is [implementation.json](implementation.json).
It records browser test results and bounded ownership snapshots, input hashes
and a before/after source fingerprint. The fingerprint is SHA-256 over sorted
`git ls-files --cached --others --exclude-standard` paths and their SHA-256
contents for `src/`, `tests/`, `scripts/issue195/`, package files and root
TypeScript/Vite/Playwright configuration. Documentation is outside this code
fingerprint. No source file changed during the acceptance run.

The host is the research machine: Apple M5 Max, 18 logical CPUs, 64 GiB RAM,
arm64 macOS/Darwin 25.5.0, Chromium 151.0.7922.34, ANGLE Metal / driver 26.5.1.
Mediabunny is 1.50.9, Playwright 1.62.1 and Vite 8.1.1. Ordinary headed tests
use 1440×900 and additionally check a 720×800 viewport. The machine is not
reserved against unrelated user activity. No other browser engine is qualified.

Synthetic clips are 20 seconds of 1280×720, 30 fps AVC with a one-second GOP
and a silent AAC track. Matrix files are independent imports of the same
encoded content; they are not recordings from eight distinct physical cameras.
The unsupported-source case uses VP9. Fresh proxies are generated by the
production proxy controller, including its provenance and cache checks.

The recorded-media case imports the [MDN flower recording](https://developer.mozilla.org/shared-assets/videos/flower.mp4),
linked by [MDN's video documentation](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video),
as two independent files and generates production proxies. Its SHA-256 is
`0cd83d944a6ca7822b4a8306cecc60a36e859b041f6702c6a1ad9ead78924451`.
Source facts: AVC `avc1.64001f`, 960×540, approximately 29.97 fps, 5.005-second
video, stereo AAC at 48 kHz, 5.056-second audio, zero video origin. The import
explicitly keeps the project's 30 fps through the normal mismatch dialog.
The file remains a local fixture, not a checked-in binary.

The browser matrix checks keyboard cuts at frames 89/90, active-angle truth,
stable focus, narrow layout, 2/4/8 admission, real proxy removal, Source Monitor
priority, derived-data clearing, project navigation, unsupported VP9 fallback,
original-media export with decoded video/audio, recovery-journal reopen and
original relink with preserved cuts. Eight repeated playback/seek cycles each
sample six seconds of live four-angle monitoring and assert terminal worker,
bitmap, lease and canvas release. This is a roughly minute-long repeated-session
probe, not multi-hour process-memory plateau evidence. Product runtime health
uses distinct Program completions; the separate research matrix measured
changing presented pixels. They are not interchangeable frame-rate metrics.

Native lifecycle evidence uses a separately spawned, muted Chromium with a
disposable profile, `connectOverCDP({ noDefaults: true })` and its actual default
context. It verifies real hidden visibility, initial-hidden admission refusal,
visible-to-hidden retirement, hidden freeze/thaw, and GPU-process-loss fallback.
The Vite HMR client connection alone is disabled using its pinned local source
string, because reconnecting after thaw otherwise reloads the page. Browser
visibility, lifecycle and native media APIs are not patched. The test kills
only its owned browser PID and removes only its disposable profile.

## Reproduction and honest limits

```sh
npm test -- --maxWorkers=4
npm run build
npm run lint
npm run qa:issue195:check
ISSUE195_RECORDED_MP4=/absolute/path/flower.mp4 npm run test:browser -- tests/browser/issue-195-monitor.spec.ts
```

Issue #195 acceptance and research Chromium launches are muted. New media
fixtures contain silent audio; audio scheduling and exported PCM are inspected
without speaker output. Historical research artifacts retain their original
facts and hashes; they have not been rewritten to pretend those runs were silent.
Ordinary automation stays headless; visual review uses the in-app browser.
The native lifecycle test is skipped unless `ISSUE195_NATIVE_LIFECYCLE=1` is
explicitly selected, since it opens/minimizes a separate browser window. Do not
enable that exception during routine QA without the user's agreement.

Final static/unit gates: production typecheck/build passed (4,979 modules),
lint passed, dedicated research typecheck and five decision tests passed, and
17 repository runner checks passed. The final full Vitest run is 3,996 passing
and one failing test across 289 files. The focused ownership regression gate
passed 97 tests, including partial preview-initialization cleanup and delayed
cooperative-close preemption.

The final source-stable headless Chromium matrix passed nine tests, with the
explicit native-window case skipped. In the last complete live health window,
2/4/8 cases each delivered about 30 distinct Program completions per second,
0.7 ms p95 completion latency, zero recorded Program errors and healthy audio
scheduling. Peak owned wall decoders were 1/3/7; peak RGBA-equivalent native
frame references were 7,372,800 / 14,745,600 / 29,491,200 bytes. The eight-angle
aggregate declared reservation was 91,929,600 bytes and 12 decoder slots,
including Program/audio. These are app ledger observations, not process RSS.
The two-angle normal-off case observed zero native inputs/decoders/frames and
scratch surfaces, with equal created/closed decoder counts and no forced close.

Desktop and narrow screenshots were reviewed. The wall now reduces its column
count when the Inspector is narrow, keeping tiles at least 76 px wide; the
existing Inspector scroll/focus controls expose the remaining rows. The in-app
editor opened without console warnings/errors. Its native import chooser was
not available to automation, so media-path acceptance comes from the headless
matrix, not a claimed in-app media run.

The full Vitest suite has an existing plugin-startup `safe-mode` failure in
`pluginAppController.test.ts`, reproduced on isolated unchanged `3653c9a` before
implementation. It is not reported as a green full suite. Earlier harness
failures included a proxy setup race, the unhandled recorded-media frame-rate
dialog, and invalid visible-page freezing / Vite reconnect behavior. These were
corrected and rerun; rejected runs are not counted as acceptance evidence.
The first complete headed product matrix passed nine cases but lost the native
browser while restoring a minimized window; the exit cause is unknown. A
separate three-run native repetition passed twice; the other run correctly
remained paused after thaw but failed the harness's automatic-resume expectation.
Native retirement evidence is retained separately from those failed attempts.
The opt-in harness now starts its independent GPU fault in a fresh project,
since automatic post-freeze recovery is not qualified. That final visible-test
adjustment was not rerun after the user requested no further Chrome windows.
This is an explicit remaining harness-validation limitation, not a claimed
green native repetition matrix.

Constrained physical hardware, other browser engines, broader AVC/GOP/rotation
recordings, physical device removal, automatic GPU recovery, multi-hour native
memory growth and reliable OS memory-pressure notification remain unqualified.
Deterministic tests cover budget rejection, late startup/close races, gaps,
signed/nonzero origins, reordered/VFR packet selection, long GOP rejection and
late-frame closure. Unit injection is not presented as hardware pressure proof.
The opt-in wall remains subject to its conservative admission and runtime
fallback on every run. The existing wider browser suite was not rerun for this
change; its earlier baseline failures remain separately documented.
